🛠️ Вокзал.ТЕХ — Порядок разработки и управления проектом ​

🧭 Методология ​

  • Гибридный подход: Scrum + Kanban
  • Спринты: 2 недели
  • Роли: Product Owner, Scrum Master, Разработчики, Тестировщики, DevOps

📅 Этапы разработки ​

1. Планирование (Sprint Planning) ​

  • Определение приоритетов (по бизнес-ценности)
  • Разбивка задач на user stories
  • Оценка сложности (в story points)

2. Разработка ​

  • Каждая задача — отдельная ветка в Git: feature/ticket-sale-validation
  • Pull Request (PR) — обязательный этап
  • Код-ревью — минимум 1 человек

3. Тестирование ​

  • Unit-тесты (Go, React)
  • Integration-тесты (API)
  • E2E-тесты (Cypress): сценарии продажи, возврата, посадки

4. CI/CD ​

  • Автоматическая сборка на каждый push
  • Запуск тестов
  • Деплой в staging
  • Ручное подтверждение → production

📦 Управление репозиториями ​

Структура ​

github.com/vokzal-tech/ ├── core-* # микросервисы (Go) ├── ui-* # фронтенды (React, Tauri) ├── agent-* # агенты (Go) ├── docs # документация ├── infra # Kubernetes, Terraform └── tools # скрипты, генераторы

Ветки ​

  • main — production
  • staging — тестирование
  • feature/* — новые функции
  • hotfix/* — срочные исправления

🧪 Тестирование ​

Уровни ​

  1. Unit — на уровне функций
  2. Integration — взаимодействие сервисов
  3. E2E — сценарии пользователя
  4. Нагрузочное — 100+ касс одновременно
  5. Регрессионное — после каждого релиза
