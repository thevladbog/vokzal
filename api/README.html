🏗 Обзор архитектуры ​

Вокзал.ТЕХ использует микросервисную архитектуру с API Gateway (Traefik) для маршрутизации запросов.

┌─────────────┐
│   Клиент    │
└──────┬──────┘
       │
┌──────▼──────┐
│  Traefik    │  API Gateway
│  (Gateway)  │
└──────┬──────┘
       │
       ├─────────► Auth Service      (порт 8081)
       ├─────────► Schedule Service (порт 8082)
       ├─────────► Ticket Service   (порт 8083)
       ├─────────► Fiscal Service   (порт 8084)
       ├─────────► Payment Service  (порт 8085)
       ├─────────► Board Service    (порт 8086)
       ├─────────► Notify Service   (порт 8087)
       ├─────────► Audit Service    (порт 8088)
       ├─────────► Document Service (порт 8089)
       └─────────► Geo Service      (порт 8090)

🎯 Сервисы ​

Auth Service ​

Порт: 8081
Спецификация: auth-service.yaml

Сервис аутентификации и авторизации:

  • Логин/логаут
  • JWT токены (access/refresh)
  • RBAC (роли: admin, dispatcher, cashier, controller)
  • Управление пользователями

Базовый URL: /api/v1/auth

Основные эндпоинты:

  • POST /login - Аутентификация
  • POST /refresh - Обновление токена
  • POST /logout - Выход
  • GET /validate - Валидация токена
  • GET /users - Список пользователей
  • POST /users - Создание пользователя

Schedule Service ​

Порт: 8082
Спецификация: schedule-service.yaml

Сервис управления расписанием:

  • Станции, маршруты, расписания, рейсы
  • Справочники автобусов и водителей
  • Генерация рейсов по расписанию
  • Статистика для дашборда

Базовый URL: /api/v1/schedule

Основные эндпоинты:

  • GET/POST/PATCH/DELETE /stations — станции
  • GET/POST/PATCH/DELETE /routes — маршруты
  • GET/POST/PATCH/DELETE /schedules — расписания
  • GET/POST/PATCH /trips, PATCH /trips/:id/status, PATCH /trips/:id — рейсы (в т.ч. статус, перрон, автобус, водитель)
  • POST /trips/generate — генерация рейсов на период
  • GET/POST/PATCH/DELETE /buses — автобусы
  • GET/POST/PATCH/DELETE /drivers — водители
  • GET /stats/dashboard?date= — статистика рейсов за дату

Ticket Service ​

Порт: 8083
Спецификация: ticket-service.yaml

Сервис управления билетами:

  • Продажа билетов
  • Возврат билетов (блокировка за 24ч до отправления)
  • Бронирование
  • Посадка пассажиров

Базовый URL: /api/v1/ticket

Основные эндпоинты:

  • POST /tickets - Продажа билета
  • GET /tickets/{id} - Информация о билете
  • POST /tickets/{id}/cancel - Отмена билета
  • POST /tickets/{id}/refund - Возврат билета
  • POST /bookings - Бронирование
  • POST /boarding/scan - Посадка пассажира

Fiscal Service ​

Порт: 8084

Сервис фискализации (54-ФЗ, АТОЛ ККТ, Z-отчёты).

Payment Service ​

Порт: 8085

Сервис обработки платежей:

  • Tinkoff Acquiring
  • Система Быстрых Платежей (СБП)
  • Наличные и терминал

Board Service ​

Порт: 8086

Сервис табло отправлений:

  • WebSocket для real-time обновлений
  • Общее табло
  • Перронное табло

Notify Service ​

Порт: 8087

Сервис уведомлений:

  • SMS (SMS.ru)
  • Email
  • Telegram
  • TTS (объявления на вокзале)

Audit Service ​

Порт: 8088

Сервис аудита (152-ФЗ).

Document Service ​

Порт: 8089

Сервис генерации документов:

  • Билеты (формат ПД-2)
  • Кастомные PDF шаблоны
  • Отчёты

Geo Service ​

Порт: 8090

Сервис геолокации:

  • Интеграция с Yandex Maps
  • Маршруты на карте
  • Геокодирование

🔐 Аутентификация ​

Большинство API эндпоинтов требуют аутентификации через JWT токен.

Получение токена ​

bash
POST /api/v1/auth/login
Content-Type: application/json

{
  "username": "admin",
  "password": "password123"
}

Ответ:

json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expires_in": 86400,
  "user": {
    "id": "uuid",
    "username": "admin",
    "role": "admin"
  }
}

Использование токена ​

Добавьте заголовок Authorization ко всем запросам:

bash
GET /api/v1/schedule/trips
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

Роли и права доступа ​

РольОписаниеДоступ
adminАдминистраторПолный доступ
dispatcherДиспетчерУправление расписанием, рейсами
cashierКассирПродажа и возврат билетов
controllerКонтроллёрПосадка пассажиров, сканирование билетов

📊 Коды ответов ​

КодОписание
200Успешный запрос
201Ресурс создан
204Успешно, без содержимого
400Неверный запрос
401Не авторизован
403Доступ запрещен
404Ресурс не найден
409Конфликт (например, дубликат)
500Внутренняя ошибка сервера

Формат ошибок ​

Все ошибки возвращаются в едином формате:

json
{
  "error": "Unauthorized",
  "message": "Invalid or expired token",
  "code": "UNAUTHORIZED"
}

👀 Просмотр документации ​

Swagger UI ​

Для просмотра интерактивной документации используйте Swagger UI:

bash
# Установка Swagger UI (если еще не установлен)
npm install -g swagger-ui-watcher

# Запуск для конкретного сервиса
swagger-ui-watcher docs/api/auth-service.yaml

# Откроется в браузере по адресу http://localhost:8000

Редактор OpenAPI ​

Для редактирования спецификаций рекомендуется использовать:

  • Swagger Editor (онлайн)
  • Stoplight Studio (desktop)
  • VS Code OpenAPI Extension

Генерация клиентов ​

Для автоматической генерации клиентов используйте OpenAPI Generator:

bash
# Go клиент
openapi-generator-cli generate \
  -i docs/api/auth-service.yaml \
  -g go \
  -o clients/go/auth

# TypeScript клиент
openapi-generator-cli generate \
  -i docs/api/auth-service.yaml \
  -g typescript-axios \
  -o clients/ts/auth

🧪 Тестирование API ​

Коллекции Postman/Insomnia ​

Для тестирования API вы можете:

  1. Импортировать OpenAPI спецификации в Postman/Insomnia
  2. Использовать автоматически сгенерированные коллекции

curl примеры ​

bash
# Логин
curl -X POST http://localhost:8081/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "password123"}'

# Получить список рейсов
curl http://localhost:8082/api/v1/schedule/trips \
  -H "Authorization: Bearer YOUR_TOKEN"

# Продажа билета
curl -X POST http://localhost:8083/api/v1/tickets \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "trip_id": "uuid",
    "passenger_full_name": "Иван Иванов",
    "passenger_phone": "+79001234567",
    "passenger_document": "4510 123456",
    "seat_number": 12,
    "payment_method": "cash"
  }'

📝 Версионирование ​

API использует версионирование через URL: /api/v1/...

При внесении breaking changes будет создана новая версия API (v2, v3 и т.д.), при этом старые версии будут поддерживаться минимум 6 месяцев.
